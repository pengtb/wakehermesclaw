# WakeHermesClaw

スマートフォンを、いつでも呼び出せる AI アシスタントに変えます。ウェイクワードを話す、クイック設定タイルをタップする、ナビゲーションバーを長押しする、あるいはイヤホンのボタンを 1 回押す——それだけで音声パネルがせり上がります。話した内容は PC 上で動くバックエンド（Hermes Agent または OpenClaw）に送られ、回答が読み上げられます。話すだけでなく、アシスタントはこのスマートフォンを逆に操作することもできます——画面の読み取り、タップ、写真撮影、SMS 送信、位置情報。

これは [openclaw-assistant](https://github.com/yuga-hashimoto/openclaw-assistant) をベースにした個人利用向けのフォークで、主な作業は Hermes Agent への接続と、音声パイプライン・バックエンド選択・スマホ操作の作り込みです。

- 最新バージョン：v2.5.2（[Releases](https://github.com/pengtb/wakehermesclaw/releases)）
- システム要件：Android 8.0 以上（minSdk 26）、targetSdk 34
- UI 言語：简体中文 / 繁體中文 / English / 日本語 / 한국어 / Deutsch / Español / Français / हिन्दी / Русский

## できること

### 音声対話

- **4 つの呼び出し方法**：ウェイクワード、クイック設定タイル、システムアシスタントのジェスチャー（ナビゲーションバー長押し / 電源ボタン）、アプリの静的ショートカット。アプリ内の「音声対話」を直接タップしても起動できます。
- **連続対話**：回答が終わると自動的に聞き取りを再開します。トランシーバーモードに切り替えることもでき、1 回タップで話し始め、もう 1 回タップで終了して送信します。
- **終了ワード**：「終了」「exit」といった言葉で対話をそのまま終了します。デフォルトのワードは UI 言語に応じて変わり、設定で自分で変更できます。
- **パネルは通知を邪魔しない**：音声パネルは画面下部に密着したカードで、上部のステータスバーはシステムに残るため、対話中でも通知シェードを引き下ろしたり承認をタップしたりできます。
- **実行中の状態**：対話中はステータスバーに通知が 1 件残り、それをタップすると対話パネルに戻ります。パネルがフォアグラウンドにあるときは「音声対話中」、バックグラウンドに移ると「タップして音声対話に戻る」と表示され、対話が終わると通知は自動的に消えます。

### 音声認識（STT）

4 つのバックエンドから用途に応じて選択できます：

| バックエンド | 説明 |
| --- | --- |
| システム認識 | スマホ標準の認識サービスを使用。設定不要 |
| OpenAI 互換 | 自前で `/v1/audio/transcriptions` サービスを立てて、バッチでアップロード |
| FunASR ストリーミング | ローカルの FunASR。話しながら文字が出る |
| Huawei HMS（ML Kit） | デバイス側認識。HMS Core と AGC の API Key が必要。**中国語と英語のみ対応** |

認識パイプラインには 2 つのフォールバックがあります。区間全体で文字が取れないときの無音タイムアウトと、Huawei SDK が final フレームでコールバックしないときにクライアント側で 1 回だけ終端処理を補う仕組みです。

### 音声合成（TTS）

| プロバイダー | 説明 |
| --- | --- |
| ローカル（システム TTS） | デフォルト。エンジンを明示的に選んでいない場合は Google TTS を優先し、次にシステムデフォルトを使用 |
| OpenAI 互換 | `POST {base}/v1/audio/speech`。URL・モデル・ボイスを設定可能 |
| Huawei HMS（ML Kit） | **クラウド**合成。ネットワーク接続と AGC API Key が必要で、毎月最初の 100 万文字まで無料。中国語と英語のみ対応 |
| ElevenLabs | 音声リストが言語に合わせてローカライズされる |
| VOICEVOX | `full` ビルドにのみ含まれる |

システムに TTS エンジンが 1 つもない場合は、Google TTS をインストールするか、オープンソースの sherpa-onnx エンジンをインストールするかの 2 つの道がダイアログで提示されます。

### バックエンドと接続方式

3 種類のバックエンドに対応しており、音声とチャットでそれぞれ独立にどれを使うかを選べます：

| 種類 | プロトコル | 用途 |
| --- | --- | --- |
| Hermes Agent | HTTP（`/v1/runs` または `/v1/chat/completions`） | メイン。システムプロンプト、ストリーミング出力、セッションに対応 |
| OpenClaw ゲートウェイ | WebSocket ノードプロトコル | スマホがノードとして接続し、ゲートウェイから直接ツール呼び出しを送れる |
| OpenClaw HTTP | OpenAI 互換 HTTP | 常時接続が不要な軽量チャネル |

- **音声セッションの接続**は 3 つから 1 つを選択：`OpenClaw ゲートウェイ` / `OpenClaw HTTP` / `Hermes HTTP`。ホームの「音声対話」上部と設定の両方に項目があり、手動で選んでいない場合はメインバックエンドに従います。
- **テキストチャット**はセッションで選んだバックエンド種別に従い、上記の設定は参照しません。
- **プロンプト**：音声とテキストチャットでそれぞれ別のシステムプロンプトを持ち、「設定 → チャット」で変更できます。空欄の場合は組み込みのデフォルトにフォールバックします。
- **音声には現場の情報が付く**：時刻、位置情報、バッテリー残量、ネットワーク、画面状態が音声リクエストごとに一緒に送信されるため、アシスタントは「今何時」「スマホの電池はどのくらい残っている」にそのまま答えられます。
- **サービスの自己修復**：音声サービスとシステムのバインドが切れると 3 段階でリトライします。デフォルトアシスタントの確認、システムバインディングの再要求、最後にプロセスの再起動です。

### スマホ操作（Mobile Bridge）

スマホ側でローカル HTTP サービス（デフォルト 8787）を起動し、Hermes はそれを介してスマホの機能を逆方向に呼び出します。画面の読み取りと UI 操作（`screen.tap/swipe/long_press/drag/back/home`、`screen.find_nodes`、`screen.window.describe`）、スクリーンショット（2 段階、JPEG）、カメラ撮影、位置情報、SMS、連絡先、カレンダー、通知の読み取りと消去、クリップボード、メディア操作（`media.play_pause/next/previous`、加えて `media.status` で曲名・アーティスト・アルバム・再生位置を取得）、音量と明るさ、アプリ一覧（`apps.list`、ランチャー登録のあるアプリを `system` / `launchable` 付きで列挙）と起動（`apps.launch`、起動後に前面が本当に切り替わったか検証）。

- 1 回だけのペアリング：アプリでブリッジを有効にすると 6 桁のペアリングコードが表示され、PC 側でそのコードを token と交換すれば、以後はペアリング不要になります。
- 権限付与と承認：ケイパビリティ単位のグループで権限を付与し、リスクの高い操作（SMS 送信、写真撮影、UI 操作）は確認ダイアログを経由します。別途レート制限もあります。
- LAN または Tailscale 内でのみ有効にすることを推奨します。バインドモードを LAN/VPN にしないと接続できません。
- **これはオプション機能です**：OpenClaw ゲートウェイを使う場合、ゲートウェイ自体がスマホのケイパビリティを送れるため、ブリッジを有効にする必要はありません。

### その他

- **ターミナル**：内蔵ターミナルは PC 上の Hermes dashboard に接続します。`hermes dashboard --tui` が必要です。
- **定期タスク**：Hermes の cron タスクの表示・新規作成・編集ができ、スクリプト（`HERMES_HOME/scripts/` からの相対パス）を指定できます。
- **診断**：ホームと設定の両方に事前チェックがあり、権限の不足、音声サービスの未バインド、バックエンド未設定、アクセシビリティ未有効などを 1 件ずつ列挙し、対処先を示します。
- **ダークモード**：設定ウィザードを含むすべての画面がシステムのライト/ダークに追従します。
- **10 種類の UI 言語**：各言語 1092 件の文言がすべて揃っており、英語が混ざることはありません。

## インストール

[Releases](https://github.com/pengtb/wakehermesclaw/releases) から APK をダウンロードしてそのままインストールできます（パッケージ名 `com.openclaw.assistant`）。

インストール後、アプリ内で次の 3 つを行います：

1. **バックエンドを追加**：「設定 → 接続」で Hermes のアドレスと token（または OpenClaw ゲートウェイのホスト / ポート）を入力します。
2. **デジタルアシスタントに設定**：本アプリをデフォルトアシスタントに設定します。設定しないとナビゲーションバーの長押しで起動できません。
3. **権限を付与**：マイクは必須です。位置情報、カメラ、SMS、連絡先、カレンダーは使いたい機能に応じて付与してください。スマホ操作を行う場合はさらにアクセシビリティサービスを有効にします。 サイドロードしたアプリは「アプリ情報 → ⋮ → 制限付き設定を許可」を先に有効にしないと、アクセシビリティをオンにできません。

音声認識と合成はデフォルトでシステムの機能を使うため、何も設定しなくても音が出て認識もできます。

## ペアリング

### Hermes バックエンド

`integrations/agentvoice-pair/` にはデスクトップ向けの小さなツールが入っています。PowerShell 版と bash 版は等価で、依存関係もありません（QR コードのエンコードと PNG の書き出しはスクリプト内で行います）。本機の Hermes API アドレス（Tailscale Serve を優先し、次に LAN）、API key、さらに dashboard の Terminal アドレスと session token を検出して、ペアリング用の QR コードを 1 枚生成します：

```bash
bash install.sh                # agentvoice-pair としてインストール。Windows では .ps1 を導入し .cmd ラッパーも生成
agentvoice-pair --open --svg   # QR コードを生成して開く
```

QR コードの中身は 1 本のディープリンクです：

```
agentvoice://setup?hu=<APIアドレス>&hk=<key>&hm=<profile>&hr=1&hs=1&htu=<dashboardアドレス>&htt=<session token>
```

`hu` / `hk` は Hermes のアドレスと API key、`hm` は対象の profile、`hr=1` は Runs API をデフォルトで使うこと、`hs=1` はストリーミング、`htu` / `htt` はターミナル用の dashboard アドレスと session token を表します。`hu` は複数指定でき、複数のアドレスは候補として並行に速度測定されます。スマホ側は 3 つの方法のどれでも構いません：システムカメラでスキャン（リンクを開くとアプリに戻ります）、アプリ内スキャン、または設定ウィザードでこの JSON / ディープリンクを直接貼り付け。

QR コードには API key と session token が含まれ、パスワードと同等です。外部に共有しないでください。

### Mobile Bridge

1. スマホで「設定 → モバイルブリッジ」を開き、有効にすると 6 桁のペアリングコードと `agentvoice://pair?u=<ブリッジアドレス>&c=<ペアリングコード>` のディープリンクが表示されます。
2. PC 上で `agentvoice-pair --code <ペアリングコード> --write-env <パス>` を実行するか、`{"code":"<ペアリングコード>"}` を `http://<スマホ>:8787/pair` に直接 `POST` します。
3. 返ってきた token を `.env` の `AGENT_VOICE_BRIDGE_URL` / `AGENT_VOICE_BRIDGE_TOKEN` に書き込みます。以後の呼び出しでは毎回 `Authorization` ヘッダーに `Bearer` とこの token を付けます。

ペアリングコードは 1 回限りで、有効期限があります。token を取得した後はペアリング不要になりますが、SMS 送信・写真撮影・タップといったリスクの高いケイパビリティは引き続き毎回承認ダイアログを経由します。

## ソースからビルド

JDK 17 と Android SDK 35 が必要です。

```bash
./gradlew assembleStandardDebug     # デバッグビルド（パッケージ名に .debug が付き、リリース版と共存可能）
./gradlew assembleFullDebug         # VOICEVOX を含むデバッグビルド
./gradlew assembleStandardRelease   # リリースビルド
```

成果物は `app/build/outputs/apk/<flavor>/<buildType>/` に出力されます。

ビルド上の注意点：

- `app/google-services.json` はリポジトリに含めません。実際の Firebase 設定がない場合は `FIREBASE_ENABLED=false` でビルドする必要があります。そうしないと mock の設定で Firebase が初期化されます。
- release ビルドにはローカルの署名設定（`local.properties` の `storeFile / storePassword / keyAlias / keyPassword`）が必要です。
- release ビルドでは `uploadCrashlyticsMappingFileStandardRelease` を除外する必要があります。そうしないと Firebase への接続を試みます。
- R8 では HMS SDK が参照するデバイス側クラス（`com.huawei.libcore.*`、`org.chromium.net.*`）を残す必要があります。ルールは `app/proguard-rules.pro` にあります。
- Huawei の key は `local.properties` の `hms.asr.key / hms.asr.appid / hms.asr.cert` から `BuildConfig` に注入され、リポジトリには含めません。release ビルドには TTS の key が含まれないため、ユーザーがアプリ内で自分で入力する必要があります。

## コード構成

```
app/src/main/java/com/openclaw/assistant/
├── speech/      認識（システム / OpenAI 互換 / FunASR / HMS）、合成（ローカル / ElevenLabs / OpenAI 互換 / HMS / VOICEVOX）、終了ワード
├── backend/     バックエンドの抽象化とディスパッチ：Hermes HTTP、OpenClaw ゲートウェイ、OpenClaw HTTP
├── service/     音声対話サービスとセッションパネル、ウェイクワード、タイル、通知、自己修復
├── bridge/      Mobile Bridge：HTTP サービス、ケイパビリティ実装、アクセシビリティ、承認と権限
├── node/        ゲートウェイノードプロトコルとランタイム
├── ui/          ホーム、チャット、設定、ターミナル、定期タスク、診断
└── data/        設定とローカルストレージ
```

- `AGENT.md` はメンテナ向けのドキュメントです。踏んだ罠、なぜそう書いたか、どこを変えると黙って壊れるかを記しています。
- `docs/hermes-mobile-bridge.md` はブリッジのプロトコルとペアリングの流れを記録しています。
- `integrations/` にはデスクトップ側のペアリングツールが入っています。

## 上流から何を変えたか

上流は `yuga-hashimoto/openclaw-assistant` です。このフォークで加えた変更を、機能ごとにまとめます：

**Hermes バックエンド**

- Hermes Agent を一級のバックエンドとして接続し、`/v1/runs` と `/v1/chat/completions` のどちらも使えます。セッション、ストリーミング、システムプロンプトもすべて通ります。Runs API の system メッセージはトップレベルの `instructions` に置く必要があり（`input` に入れてもサーバー側は読みません）、この点はクライアント側で補いました。
- 接続方式は 3 つから 1 つを選択：OpenClaw ゲートウェイ / OpenClaw HTTP / Hermes HTTP。ホームと設定の両方に項目があり、選択に厳密に従うため、黙ってフォールバックすることはありません。
- アドレスに `/v1/` がない場合は自動で補完します。旧設定を移行した後にメッセージを送ると 404 になる問題を修正しました。

**音声**

- 認識をプラガブルなマルチバックエンドに変更：システム / OpenAI 互換バッチ / FunASR ストリーミング / Huawei HMS。元の Baidu バックエンドは削除しました。
- Huawei HMS のクラウド合成を追加。端末に TTS エンジンが 1 つもない場合はインストールガイドを表示します。
- 音声とテキストチャットのシステムプロンプトを分離して変更可能にし、空欄ならデフォルトにフォールバックします。
- 音声リクエストに時刻・位置情報・バッテリー残量・ネットワーク・画面状態を自動で付加します。
- 終了ワード：話すとそのセッションを終了し、デフォルトのワードは UI 言語に応じて変わります。
- 呼び出し方法を 3 つ追加：クイック設定タイル、`VOICE_COMMAND` 経由のジャンプ、静的ショートカット。
- 音声サービスとシステムのバインドが切れた場合は 3 段階で自己修復：デフォルトアシスタントの確認 → バインディングの再要求 → プロセスの再起動。
- パネルを画面下部に密着したカードに変更し、通知シェードを覆わないようにしました。対話中の通知はフォアグラウンド/バックグラウンドで文言が変わり、タップでパネルに戻り、終了すると消えます。

**スマホ操作**

- スクリーンショットと写真撮影はどちらも 2 段階です。まずメタデータと短命の id を返し、その id で base64 を取得します。画像はメモリ上にのみ保持し、5 分で失効し、ディスクには書き出しません。
- 写真撮影は「承認で武装」するカメラのフォアグラウンドサービスを使い、Android 12 以降のバックグラウンドからのカメラサービス起動制限を回避しています。
- SMS 送信は `sentIntent` の結果を待ってから返すように変更し、実際の結果コードを返します。
- アクセシビリティのジェスチャーはメインスレッドでディスパッチしてコールバックを待つようにし、tap / swipe が黙って効かなくなる問題を修正しました。`screen.window.describe` はアクティブウィンドウから取得するため、パッケージ名の誤報告もなくなりました。
- ケイパビリティグループに `location` / `screen` を追加。ブリッジ状態カードは「現在の設定 / 適用予定」の 2 行に分かれ、設定を変えた直後に見比べられます。
- `media.status` を追加：再生中のアプリ、曲名、アーティスト、アルバム、再生位置と状態を取得（既存の 3 つの操作キーと併用）。
- `apps.list` はランチャー登録単位で列挙し `system` / `launchable` を付与（`<queries>` に MAIN/LAUNCHER を宣言、`QUERY_ALL_PACKAGES` は不要）。
- `apps.launch` は起動後に前面が切り替わったか検証し、無条件に成功を返さない。
- ブリッジの accept ループが `IOException` 1 回で終了しないようにし、「ポートは待ち受けているのに接続がすべてタイムアウトする」状態を解消。

**日常利用**

- ホーム・設定・ウィザードの 3 か所に事前チェックがあり、実行時権限とアクセシビリティサービスをカバーし、各項目に「対処する」が付いています。
- 10 種類の UI 言語すべてで 1092 件を翻訳済みにして、言語リストから選択できます。
- ダークモードが設定ウィザードとバックエンド管理ページにも適用されます。
- ターミナルに dashboard アドレスと session token のフィールドを追加。定期タスクにはスクリプト行を追加し、interval / once タスクで `expr` が必須なためにリスト全体のデシリアライズが失敗する問題を修正しました。
- 設定ページの下部にビルドの短縮ハッシュを表示し、同じバージョン番号でもビルドごとに区別できます。

変更の詳細は `git log` を照合してください。アーキテクチャ上の判断と踏んだ罠は `AGENT.md` に書いてあります。

## 既知の制限

- `brightness.set` には `WRITE_SETTINGS` が必要で、権限がない場合はケイパビリティが表示されません。
- 自前ビルド（パッケージ名が異なる）では Google Play の ML Kit スキャンモジュールを取得できず、アプリ内のスキャンは使用できません。システムカメラでディープリンクの QR コードを読み取ることで回避できます。
- Huawei HMS の認識と合成は中国語と英語のみ対応しています。
- OpenClaw ゲートウェイと OpenClaw HTTP の 2 つのチャネルは、作者の環境にサーバーがなくテストできていないため、実機での検証は行っていません。

## 謝辞

本プロジェクトは 2 つのオープンソースプロジェクトの上に成り立っています：

- [openclaw-assistant](https://github.com/yuga-hashimoto/openclaw-assistant)（作者 yuga-hashimoto、MIT）— このフォークの出発点で、UI・音声インタラクション・ゲートウェイ・ノード機能はここに由来します。上流の README は本文書に置き換えました。
- [gpt-assistant-android](https://github.com/Skythinker616/gpt-assistant-android)（作者 Skythinker616、GPL-3.0）— 音声認識層の「共通インターフェース + 複数バックエンド」構成は同プロジェクトの `AsrClientBase` 設計を参考にしており、Huawei HMS ML Kit の組み込み方も参考にしています。実装は同じ考え方で独自に行ったもので、コードの流用はありません。
